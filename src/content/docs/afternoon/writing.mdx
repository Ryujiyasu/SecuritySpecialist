## 答案の構造テンプレート

字数別に「型」を持っておく。型に問題文の固有条件をはめ込めば、考える時間を節約できる。

<Mermaid code={`flowchart TD
  Q[設問を読む] --> P{問われているのは?}
  P -->|理由| R[条件 + 帰結 + 結論]
  P -->|対策| C[手段 + 効果]
  P -->|問題点| I[現状 + 基準 + ギャップ]
  P -->|具体的な値/名| V[問題文から抽出]
  P -->|手順| S[番号付きで順序立て]
  R --> A[答案完成]
  C --> A
  I --> A
  V --> A
  S --> A
`} />

### 型 1: 理由 (40〜80 字)

> **\{問題文の事実\} のため、\{問われている事象\} が発生する/必要となる。**

例 (50 字):
> 委託先がリモートで本番 DB を直接操作するため、操作ミスや不正の事後追跡が必要となる。

### 型 2: 対策 (50〜100 字)

> **\{具体的な手段\} を行うことで、\{攻撃の成立要因\} を \{防ぐ / 検知する / 影響を抑える\}。**

例 (80 字):
> 入力値を SQL クエリのプレースホルダで処理することで、ユーザ入力が SQL 文として解釈されることを防ぎ、SQL インジェクションの成立を阻止する。

### 型 3: 問題点 (50〜100 字)

> **\{現状の事実\} は、\{基準・あるべき姿\} に反しており、\{想定される被害\} のおそれがある。**

例 (90 字):
> 開発者が本番 DB の更新権限を保有している点。職務分離の原則に反しており、誤操作や不正により本番データが改変・削除されるおそれがある。

### 型 4: 手順 (100〜200 字)

番号付きで時系列順に。手順間の依存関係を明示。

例:
> 1. メモリダンプを取得する。  
> 2. ネットワーク接続を遮断する。  
> 3. ディスクのフォレンジックイメージを取得する。  
> 4. ハッシュ値で同一性を確認した上で、解析を別環境で実施する。

## 動詞辞書 (採点者が好む言い回し)

| カテゴリ | 推奨動詞 | NG な代替 |
| --- | --- | --- |
| 確認 | 検証する、判定する、照合する | チェックする (口語的) |
| 防止 | 阻止する、無効化する、遮断する | ブロックする (漠然) |
| 検知 | 検出する、発見する、識別する | 見つける |
| 制限 | 限定する、制限する、最小化する | 絞る |
| 暗号化 | 暗号化する、機密性を確保する | 隠す |
| 監視 | 監視する、追跡する、記録する | 見張る |

<div class="sc-key">
**「〜することで、〜を防ぐ」** という構造は採点者にとって読み解きやすい。
1 文に「手段 → 効果」が含まれるため、部分点が拾いやすい。
</div>

## 減点される言い回し (避ける)

| ❌ NG | ✅ OK |
| --- | --- |
| 適切な権限管理を行う | 業務上必要な最小権限のみを付与する |
| しっかりと確認する | 申請書類と DB の権限定義を照合する |
| セキュリティを強化する | 多要素認証を導入し、不正ログインを防ぐ |
| 厳重に管理する | アクセスログを取得し定期的に監査する |
| ちゃんと暗号化する | TLS 1.3 で通信を暗号化する |
| しっかりログを取る | 認証成否・操作内容・送信元 IP を記録する |
| 万全な対策を取る | 多層防御 (FW/IDS/WAF) を導入する |

<div class="sc-trap">
**「適切」「しっかり」「万全」「ちゃんと」「適宜」「随時」**は答案ゴミ語。
これらが入っている設問は採点で点を引かれている可能性が高い。
具体性のない言葉を見つけたら**書き直す**。
</div>

## 用語の使い分け

午後で間違えやすい用語ペア。

| ペア | 違い |
| --- | --- |
| 認証 / 認可 | 認証 = 誰か / 認可 = 何ができるか |
| 完全性 / 可用性 / 機密性 | CIA 三要素。**改ざん防止 / 利用可能性 / 漏えい防止** |
| 真正性 / 完全性 | 真正性 = 主張通りの主体である / 完全性 = データが正しい状態で保たれる |
| 暗号化 / ハッシュ化 | **可逆 / 不可逆** |
| 検知 / 防御 | IDS (検知) / IPS (検知+遮断) |
| 脆弱性 / 脅威 / リスク | **欠陥 / 攻撃要因 / 損害発生の可能性** |

### ログ抜粋問題

ログの読み方:
1. **時系列** で並べ直す (時刻を見る)
2. **送信元 / 宛先** をマーキング
3. **異常な箇所** (失敗コード、見慣れないユーザ) を丸で囲む
4. **正常パターンと比較** して差分を抽出

## 解答用紙の書き方 (物理的なコツ)

- **濃い HB 鉛筆** + 消しゴム (シャーペン可だが芯が薄いと読みにくい)
- 字は**整える必要はない**が **採点者が読める** 程度に
- **罫線をはみ出さない** (字数オーバーで減点リスク)
- 一度書いた答えを大幅に書き換えるなら、**最後まで答え切ってから戻す**
- **単位 (バイト, 秒, 件)** は必ず明記

## 確認問題

<details class="sc-answer">
<summary>Q1. 「設問: SSL VPN 利用時のセキュリティリスクを 80 字以内で述べよ。」良い答案の例を書け。</summary>

**A. 例 (75 字):**
> SSL VPN 装置自身に深刻な脆弱性が公表される事例があり、装置を起点にした内部侵入や認証情報窃取により、社内ネットワーク全体への侵害につながる。

ポイント: 一般論ではなく「**装置自体の脆弱性**」という具体リスクを挙げ、「社内全体への侵害」という影響まで結論づけている。
</details>

<details class="sc-answer">
<summary>Q2. 「適切な権限管理を行う」を採点者好みに書き換えよ。</summary>

**A. 例:**
> 業務上必要な最小権限のみをロールに割り当て、ロールへの割当を申請承認制で管理する。

「適切な」を **具体的な原則 (最小権限) + 仕組み (申請承認)** に置き換える。
</details>
