## 個人情報の階層構造

法律上の用語は段階的に重ねられている。混同しないこと。

<Mermaid code={`flowchart TD
  A[個人情報] --> B[個人データ]
  B --> C[保有個人データ]
  A --> D[要配慮個人情報]
  A --> E[個人識別符号]
  D -.特別扱い.-> A
  E -.含まれれば 個人情報.-> A
  style A fill:#fef2cf
  style D fill:#ffd6d6
`} />

| 用語 | 定義 (要点) | 試験の論点 |
| --- | --- | --- |
| **個人情報** | 生存する個人を識別できる情報 | 死者の情報は含まない |
| **個人データ** | 個人情報データベース等を構成する個人情報 | 検索可能に体系化されている |
| **保有個人データ** | 事業者が開示・訂正等できる個人データ | 開示請求の対象 |
| **要配慮個人情報** | 人種、信条、病歴、犯罪歴等 | **取得時に同意必須** |
| **個人識別符号** | DNA、顔認識データ、マイナンバー等 | これだけで個人情報 |

<div class="sc-trap">
「メールアドレス単体は個人情報か？」→ **氏名等と結合して特定個人を識別できれば個人情報**。
ドメインから所属がわかる `tanaka@kyoto-u.ac.jp` のようなものは単体でも個人情報になりうる。
</div>

## 個人情報取扱事業者の主な義務

<Mermaid code={`flowchart LR
  L1[利用目的の<br/>特定 (15条)] --> L2[利用目的の<br/>通知/公表 (21条)]
  L2 --> L3[適正な取得 (20条)<br/>偽りその他不正の手段で取得しない]
  L3 --> L4[安全管理措置 (23条)<br/>技術的/物理的/組織的/人的]
  L4 --> L5[第三者提供の制限 (27条)<br/>原則 同意必要]
  L5 --> L6[漏えい時の報告 (26条)<br/>本人通知 + 個人情報保護委員会報告]
  L6 --> L7[開示・訂正・利用停止<br/>(33-35条)]
`} />

### 安全管理措置の 4 分類

| 区分 | 例 |
| --- | --- |
| **組織的** | 責任者の設置、規程、教育、監査、報告体制 |
| **人的** | 従業者教育、誓約書、退職時手続 |
| **物理的** | 入退室管理、機器の盗難防止、廃棄手順 |
| **技術的** | アクセス制御、暗号化、ログ取得、不正アクセス対策 |

<div class="sc-key">
午後の記述で「安全管理措置のうち何が不足したか」を問われたら、**4 区分のどれに該当するかを明示**する。
「組織的安全管理措置として、退職者のアカウント無効化手順が運用されていなかった」のように区分名 + 具体内容で書く。
</div>

**委託先による漏えいの責任**: 委託元 (個人情報を渡した側) は委託先を「**必要かつ適切な監督**」する義務がある (25条)。

## 漏えい等が発生したとき (令和 4 年改正で義務化)

### 報告対象 (4 類型のいずれか)

1. 要配慮個人情報を含む漏えい等
2. 財産的被害が生じうる漏えい等 (クレカ番号など)
3. 不正の目的によるおそれがある漏えい等
4. **1,000 人を超える漏えい等**

### タイムライン

<Mermaid code={`gantt
  title 漏えい時の対応タイムライン
  dateFormat YYYY-MM-DD
  section 速報
  覚知 → 速報    :a1, 2026-05-01, 3d
  section 確報

| 報告 | 期限 | 提出先 |
| --- | --- | --- |
| **速報** | おおむね **3〜5 日以内** | 個人情報保護委員会 |
| **確報** | 原則 **30 日以内** (不正アクセス等は 60 日以内) | 個人情報保護委員会 |
| 本人通知 | 速やかに | 本人 |

<div class="sc-key">
「**速報 / 確報 / 本人通知**」の 3 つはセットで覚える。期限の数字 (30 日 / 60 日) は出題されやすい。
</div>

## 越境移転 (28 条)

外国にある第三者へ個人データを提供する場合、**通常の同意では足りない**。

- 本人に **対象国の制度** + **講ずる措置** を情報提供した上で同意取得
- または、提供先が **基準適合体制** (相当措置を継続的に講じる) を整備し、定期確認

<div class="sc-trap">
「クラウドサービス事業者に個人データを保存している」→ クラウドが暗号化されて事業者から内容が見えない場合、
**第三者提供に該当しない**。一方、運用で社員が直接アクセスする SaaS は第三者提供 = 同意必要。
</div>

## 確認問題

<details class="sc-answer">
<summary>Q1. 本人の同意なしに第三者提供できるケースを 2 つ挙げよ。</summary>

**A.** 例:
1. 法令に基づく場合 (税法上の届出、警察の照会への応答 等)
2. 人の生命・身体・財産の保護に必要、かつ本人同意の取得が困難な場合
3. 委託・事業承継・共同利用 (27 条 5 項により第三者提供に該当しない)
4. オプトアウトの届出を個人情報保護委員会に行っている場合 (要配慮を除く)
</details>

<details class="sc-answer">
<summary>Q2. 委託先で個人データの漏えいが起きた。誰が報告義務を負うか。</summary>

**A.** **委託元と委託先の両方** が報告義務を負う (連名でも個別でも可)。
委託元には 25 条の監督義務があり、委託先は実際の取扱事業者として直接の義務を負う。
</details>

<details class="sc-answer">
<summary>Q3. 1,000 人未満の漏えいは報告不要か。</summary>

**A.** **必ずしも不要ではない**。要配慮個人情報、財産的被害、不正の目的のいずれかが関わる場合は、
人数に関係なく報告義務がある。
</details>
